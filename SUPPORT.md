# Support

Mellions Engineer is maintained as an open-source engineering project. The
project does not currently offer a response-time or uptime service-level
agreement.

## Installation and usage

Use a GitHub issue for a reproducible installation, configuration, CLI, hook,
or runtime-integration problem. Before filing:

1. read [`docs/install.md`](docs/install.md) and run `mellions doctor`;
2. search open and closed issues for the same failure;
3. reduce the report to the smallest safe reproduction;
4. remove tokens, private repository names, user data, hostnames, internal
   paths, and proprietary source or logs.

Include the Mellions commit or release, operating system, coding-agent runtime
and version, the command that failed, expected behavior, and sanitized output.
Use the runtime-integration issue form for a new adapter and the benchmark form
for evidence that challenges a published claim.

Support is strongest for the current release and the `dev` branch. Older
releases may be asked to reproduce on a current version before a maintainer
investigates further.

## Security and sensitive reports

Do not put an unpatched vulnerability, credential, customer data, or sensitive
infrastructure detail in a public issue. Follow [`SECURITY.md`](SECURITY.md) and
email [leta@letatech.ca](mailto:leta@letatech.ca).

## Community conduct

Participation in project spaces follows
[`CODE_OF_CONDUCT.md`](CODE_OF_CONDUCT.md). A planned chat community is not a
support contract and is not project authority; durable technical outcomes
belong on GitHub as described in [`docs/community.md`](docs/community.md).
